# Task 1: Test cases: Book an appointment

## The requirements are as stated below:

### Feature: Book an appointment

1.  A member with an active policy can book an appointment with an in-network provider.
2.  Appointments can be booked from the next available slot today up to 30 days ahead.
3.  Slots are 30 minutes long, between 08:00 and 17:00.
4.  A member can hold at most 3 upcoming appointments at a time.
5.  A booking can be cancelled free of charge up to 2 hours before the start time.
6.  After booking, the member gets an in-app confirmation and an SMS.

**BVA** = boundary value analysis. Types: P = positive, N = negative, B = boundary.

Assumptions used where the requirement is silent (these are raised as questions below):

- Slot start times are 08:00, 08:30 ... 16:30, so the last slot ends at 17:00.
- "30 days ahead" is counted in calendar days from today, with day 30 included.
- A cancelled appointment no longer counts towards the limit of 3.

## Questions for the product manager

1. **Slot boundaries:** Is 17:00 the end of the last slot (last start 16:30), or can a slot start at 17:00? Is the slot list the same for every provider, or can providers set their own hours?
2. **Cancellation within 2 hours:** What happens at less than 2 hours: is cancellation blocked, or allowed with a fee? Is exactly 2 hours before start still free? Does a cancelled appointment stop counting towards the limit of 3?
3. **Booking window and SMS failure:** Is "30 days ahead" inclusive of day 30, and which time zone is used? If the SMS fails to send, should the booking still go through, and should the member see a message?
